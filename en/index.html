Mipockle — autonomous development agent

Mipockle carries context from Slack, development tickets, documents, and meetings through requirements, implementation, verification with real data, and coordination with teammates. I design, build, and operate the system that lets it work continuously using Claude Code and Codex.

  • Implementation is delegated

    I rarely drive the terminal (TUI) myself to implement anything.

  • So is upstream communication

    The upstream communication that development needs — talking with teammates, confirming specifications — is handled by AI as well. The only part I do myself is attending the actual meetings.

  • From meetings to follow-through

    Meeting content goes to the AI too, carrying agreements and decision context into later work. It organizes responsibilities and dependencies and moves through clarification, implementation, and handoff.

  1. Understand the work and requirements

    Cross-check Slack, tickets, documents, and meetings to identify my responsibilities, agreements, and open questions, then define the change from the goal and expected outcome.

  2. Design and implementation

    Study existing code and specifications, create an issue, pull request, and isolated workspace for each change, and implement with dependencies in mind. An independent reviewer checks important design decisions.

  3. Verify real data and outputs

    Beyond tests, check incomplete input, resuming interrupted work, and actual rendering and output. A reviewer without the authoring conversation checks the result against the expected outcome.

  4. Coordination and review responses

    Within the delegated scope, handle requirements questions, progress updates, deliverable announcements, and review responses in Slack, then continue fixing and verifying from feedback.

  5. Continuous execution and handoff

    Always-on processes check requests and replies and resume work as dependencies clear. For my own products, they handle merge and cleanup; in other teams, they follow the agreed approval and release process.

  6. Memory and continuous improvement

    Retain agreements, decision context, and open questions for later work. Improve procedures from results and feedback, then check the outcomes in subsequent runs.
