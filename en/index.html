Autonomous development system

A development platform in which agents follow defined procedures from clarifying requirements all the way to merging and cleaning up. The procedures and decision rules are kept independent of the agent runtime, so the same workflow runs on both Claude Code and Codex.

  • Implementation is delegated

    I rarely drive the terminal (TUI) myself to implement anything.

  • So is upstream communication

    The upstream communication that development needs — talking with teammates, confirming specifications — is handled by AI as well. The only part I do myself is attending the actual meetings.

  • A closed context

    Meeting content is handed to the AI too, so work moves forward with every piece of context the job needs already in the AI's hands.

  1. Requirements and design

    Goals and acceptance criteria are settled through dialogue. Important decisions are challenged by a separate reviewer agent that has no access to the conversation that produced them.

  2. Implementation

    Each piece of work automatically gets its own issue, pull request, and isolated worktree, so several tasks can be implemented in parallel.

  3. Verification

    Besides tests, a reviewer agent without the authoring context checks the result against the acceptance criteria. Anything where appearance matters is checked in a real rendering.

  4. Merge and cleanup

    Merging, cleaning up branches and worktrees, and updating issues and project status are all automated.

  5. Accumulated knowledge

    The reasons and background behind decisions are saved as memories and recalled in later work. Failures feed back into fixing the procedures themselves.

  6. Always-on operation

    Resident processes pick up requests from Slack and scheduled tasks, and notify me only when a decision needs a human.
